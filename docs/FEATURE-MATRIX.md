# OhmyTesla 统一功能矩阵

> 由市场调研自动生成：汇总 TeslaFi / Tessie / Teslascope / RedDash / Sentry-Six / tesla_dashcam / SentryPro 等竞品的全部功能，标注优先级与实现要点。
> P0 = MVP 必做，P1 = 第二阶段，P2 = 长期。

## dashcam-studio

| 功能 | 优先级 | 竞品参考 | 实现要点 |
|---|---|---|---|
| Synchronized multi-camera playback (HW3 4-cam / HW4 6-cam / Cybertruck 7-cam) | P0 | RedDash, Sentry-Six, ExportDash, TDashcamStudio (DeaglePC), teslanav-viewer, Rene-Sackers TeslaCamPlayer | Probe codec/resolution per file (H.264 vs HEVC is firmware-dependent; HW4 front is 2896x1876 vs 1448x938 others) with ffprobe at ingest; align by filename timestamp + frame offsets, tolerate 59s clips with 2-3s gaps, missing/corrupt angles, and moov-at-end (faststart remux on ingest). HEVC-in-Chromium is the #1 pitfall: play natively when platform decode exists, else on-the-fly server ffmpeg transcode. |
| SEI embedded-telemetry decode + live overlay (speed, steering, pedals, gear, AP state, GPS, G-force) | P0 | Tesla official dashcam tools, RedDash, Sentry-Six, ExportDash, TeslaCamViewer (NateMccomb), TDashcamStudio, teslanav-viewer | Vendor teslamotors/dashcam dashcam.proto; decode with protobufjs in-browser (ExportDash precedent) and Python sei_extractor server-side at ingest. SEI exists only on fw 2025.44.25+ HW3+ and is absent when parked — design overlay to degrade to TeslaMate-sourced data. |
| TeslaMate-fused overlay: SOC, power/regen kW, elevation, inside/outside temp, odometer, range — data SEI lacks | P0 | Telemetry Overlay ($199, manual CSV + manual sync only) | Join TeslaMate positions (~1Hz during streamed drives) by drive window, interpolate onto video PTS; heading must be derived from consecutive lat/lon (positions has no heading column); carry-forward usable_battery_level/temps/ranges that are NULL on stream-inserted rows. This automated join is the headline moat. |
| Sentry/Saved event browser: event.json reason codes, thumbnails, map, date/type filters | P0 | RedDash, Rene-Sackers TeslaCamPlayer, teslacam-browser | Parse SentryClips/SavedClips event.json (timestamp, city, est_lat/est_lon, reason like sentry_aware_object_detection, camera, thumb.png); enrich by joining TeslaMate geofences to auto-tag events ('Sentry @ Home'). Use virtualized list for huge archives (Rene-Sackers pattern). |
| Composed video export with layouts (2x2 grid, 6-grid, PiP, cockpit, sidebar, 9:16 social-safe) + burned telemetry dashboard | P0 | RedDash, tesla_dashcam, Sentry-Six, TeslaCamViewer (NateMccomb) | Server-side ffmpeg xstack/overlay/drawtext filtergraphs with hwaccel autodetect (NVENC/QSV/VAAPI/VideoToolbox), copying tesla_dashcam's proven layout taxonomy; render telemetry gauges as a transparent overlay track composited over the camera grid. MVP ships grid + PiP + telemetry burn-in; full parity in phase 2. |
| Encrypted-clip handling (firmware 2026.20+ encrypts by default) | P0 | ExportDash, dashcam.tesla.com | Detect MP4s that fail to parse and show clear UX pointing to Controls > Safety > Encrypt Dashcam Recordings; investigate ExportDash/dashcam.tesla.com account-key local decryption as a follow-up. Ignoring this breaks every new-firmware user's first run. |
| Auto-ingest watch mode: index mounted TeslaCam USB / teslausb network share into Postgres (clips, events, SEI telemetry tables) | P1 | tesla_dashcam (--monitor), teslausb (adjacent), Sentry-Six Sentry USB | Ingest-once architecture: folder scan + event.json parse + one-time SEI extraction into OhmyTesla's own Postgres schema so timeline queries, search and analytics are instant on revisit; enables SQL joins against TeslaMate drives/positions/geofences. |
| Drive-centric footage browsing: pick a TeslaMate drive, see stitched footage + route map; click map point to seek video | P1 | none — OhmyTesla unique | Join clip wall-clock ranges to drives.start_date/end_date; render route from positions and bidirectionally sync map cursor with video PTS. All existing tools start from the USB folder tree — this inverts it. |
| Pre-SEI / parked-clip telemetry backfill from TeslaMate | P1 | none — OhmyTesla unique | For clips before fw 2025.44.25 (and parked Sentry clips with no SEI), derive speed/GPS/power/SOC overlays purely from TeslaMate positions matched by filename timestamp — instantly serves years-old archives no other tool can annotate. |
| Clock-drift auto-correction between clip filenames and TeslaMate wall clock | P1 | none (Telemetry Overlay requires manual alignment) | Cross-correlate SEI lat/lon or speed curve against TeslaMate positions to solve per-car offset (also absorbs car-local-time filenames vs UTC TeslaMate timestamps); store offset per car with a manual ±N-seconds slider fallback. |
| GPS minimap synced to playback with route colored by autopilot state, burned into exports | P1 | Sentry-Six (viewer only), ExportDash, TeslaCamViewer (NateMccomb), teslanav-viewer | MapLibre GL + OSM live in the player (works from TeslaMate positions even without SEI); for exports pre-render tiles server-side (gopro-dashboard-overlay approach) to avoid live-tile licensing/perf issues. Color segments blue FSD / gray manual from SEI autopilot_state. |
| Timeline intelligence: speed curve in scrubber, FSD/manual bands, hard-braking + honk markers, per-clip FSD% and disengagement counts | P1 | TDashcamStudio (speed curve), bt1142msstate viewer (FSD indexing, manual-driving bands) | Compute at ingest from stored SEI (autopilot_state transitions, linear_acceleration thresholds) into Postgres so scrubber bands and archive-wide searches ('all hard-braking moments') are instant. |
| Instant in-browser short-clip export (no server round-trip) | P1 | ExportDash, teslanav-viewer | WebCodecs + mp4-muxer client-side for short clips and screenshots; route multi-minute merges and 6-cam HW4 loads to the server ffmpeg pipeline where browser memory dies. |
| Privacy toolkit: manual blur zones, AI license-plate/face blur, GPS/timestamp-stripping export mode | P1 | Sentry-Six, TeslaCamViewer (NateMccomb), teslanav-viewer | WASM-local YOLOv11n plate detection (NateMccomb precedent) keeps processing client-side; privacy export mode strips GPS/timestamps — table stakes for publicly sharing sentry footage. |
| Custom drag-and-drop layout editor with shareable presets | P2 | TeslaCamViewer (NateMccomb) | Store layouts as JSON (per-camera crop/scale/position) that compiles to both the CSS player grid and the ffmpeg filtergraph, so viewer and export stay WYSIWYG. |
| Motion-only fast-forward for hours of parked Sentry footage | P2 | tesla_dashcam (--motion_only) | ffmpeg mpdecimate/scene-detection pass at export time; optionally index motion segments at ingest for scrubber hints. |
| Evidence package export: composed video + raw clips + event.json + telemetry CSV + map snapshot in one ZIP | P2 | none — OhmyTesla unique | One-click insurance/police bundle assembled server-side from already-ingested artifacts; include clock-offset metadata for chain-of-custody credibility. |
| Telemetry data export (CSV/GPX per clip or drive) and transparent-overlay-only video export | P2 | TeslaCamViewer (NateMccomb), TDashcamStudio, teslanav-viewer, Telemetry Overlay | CSV/GPX from the ingested SEI + positions tables; overlay-only export (alpha channel) serves pro editors, matching Telemetry Overlay's niche. |
| Corrupt-clip triage and moov-carve recovery for power-cut minutes | P2 | none (clipsalvage articles document the failure mode) | Detect moov-atom-missing MP4s at ingest, flag rather than fail, and offer untrunc-style carve recovery using a sibling healthy clip as reference. |

## sentry-alerts

| 功能 | 优先级 | 竞品参考 | 实现要点 |
|---|---|---|---|
| Real-time sentry event detection: Fleet Telemetry SentryMode Armed/Idle/Quiet→Aware alert, →Panic critical | P0 | SentryPro, SentryAlert, Sentry Modder, Tessie (Direct Telemetry), SentryGuard | The ONLY near-real-time source — Fleet API polling is architecturally blind (no event field, maintainer-confirmed). Push fleet_telemetry_config {SentryMode:{interval_seconds:1..30}, CenterDisplay:30, ChargePortLatch:30}; on-change delivery makes it nearly free ($0.0001/signal inside the $10/mo credit). Ingest via self-hosted teslamotors/fleet-telemetry (MQTT dispatcher into the existing mosquitto) or MyTeslaMate profile. |
| Multi-channel self-hosted-friendly push: Telegram bot with inline action buttons, ntfy, Web Push, SMTP, Apprise extensibility | P0 | SentryGuard (Telegram), MyTeslaMate (Telegram), ntfy/Apprise ecosystems | Telegram flagship (free, instant, actionable buttons proven by SentryGuard); Web Push for our PWA (document iOS 16.4+ home-screen + user-tap permission requirements); ntfy for self-hosters (warn about upstream-base-url relay for instant iOS); SMTP fallback; Apprise (BSD-2) as the 100+-service extensibility layer instead of hand-writing integrations. Avoid Gotify as default (no official iOS client). |
| Dedup + escalation state machine: collapse Aware recurrences within 15s into one incident, escalate to critical after 90s of persistence | P0 | SentryPro (15s dedup, Critical Alerts Auto mode) | Implement as an explicit FSM in the core service recording every transition with timestamps; suppress when is_user_present (TeslaMate MQTT) or a ChargePortLatch event correlates within the verification window. |
| Incident history timeline: 30-day filterable feed with location, geofence tag, state transitions | P1 | SentryAlert, Tessie, SentryPro | Persist incidents in OhmyTesla's own schema (TeslaMate never stores sentry state in Postgres — our MQTT archiver must record it); join TeslaMate geofences for place tags and render a sentry heat map. |
| Break-in detection with Sentry OFF (saves 4-8% pack/day) | P1 | SentryGuard, MyTeslaMate | Watch CenterDisplay == DisplayStateLock (locked-car touch) with delayed verification and ChargePortLatch time-correlation to suppress charge-cable false alarms — SentryGuard's verified implementation, reusable since it's AGPL-3.0 like our stack. |
| Deterrent actions from the notification: honk, flash, boombox; deep link to Tesla app live camera | P1 | SentryPro, SentryGuard, Sentry Modder | Requires the bundled teslamotors/vehicle-command signing proxy (optional compose profile); wire as Telegram inline keyboard + portal buttons with a command allowlist. |
| Incident ⇄ video auto-attach: link each sentry incident to its SentryClips footage once synced | P1 | none — OhmyTesla unique (teslausb notifies but doesn't correlate) | Match incident timestamp + est_lat/est_lon to ingested SentryClips event folders after home-WiFi sync (teslausb/Sentry-USB share); notification thread gets a follow-up 'footage available' message. |
| Republish sentry incidents to MQTT (teslamate/cars/$car_id/sentry_event style) | P1 | none — no existing product does this | Publish to the same mosquitto broker so Home Assistant/Node-RED users automate on incidents — matches TeslaMate integration culture at zero cost. |
| Backend sentry scheduling (time/geofence on-off windows) with battery-savings estimate | P2 | SentryPro, Sentry Modder, TeslaFi, Teslascope | Cron in core service issuing sentry on/off via vehicle-command proxy; show estimated kWh saved (~150W while armed on fw 2024.38+). |
| End-to-end latency health metric per incident | P2 | SentryGuard (correlationId) | Measure event timestamp vs delivery time, flag processing >1s, surface as a health panel; advertise honestly that poor LTE can delay alerts minutes (SentryPro precedent). |
